# 똑똑 TokTok · 생애여정 음악지도

어르신의 삶을 노래로 남기는 따뜻한 기록.
주야간보호센터 사회복지사가 **생애 인터뷰 → 전사 → 사실 확인 → 가사 → 노래 →
함께 부르기 → 활동일지**까지 한 흐름으로 진행하는 모바일 웹앱입니다.

1차 고객은 청주시 소재 정원 30인 이하 주야간보호센터의 센터장·프로그램 담당
사회복지사입니다.

## 지켜지는 제품 불변식

기능명세서 v1.6이 P0로 못박은 규칙을 UI 문구가 아니라 **코드로** 강제합니다.

| 원칙 | 어디서 강제되나 |
| --- | --- |
| 검증된 사실만 생성 (원칙 2) | `StoryItem.sources`는 비어 있을 수 없고, `assertStoryIntegrity()`가 이를 검사 |
| 미확인 항목 차단 (NFR-AI-003) | `lyricInputs()`만이 가사 입력을 만들 수 있고, `assertOnlyVerified()`가 마지막 관문 |
| 사람 검수 필수 (원칙 3) | 가사·활동일지는 사람이 승인하기 전까지 `draft` |
| 본인 최종 통제 (원칙 1) | 이야기 정리에서 어르신이 언제든 확인/보류/제외로 옮길 수 있음 |
| 목적별 분리 동의 (원칙 4) | 5종 동의가 독립 스위치이고, 거부 시 대체 경로를 그 자리에서 안내 |
| 동의 없으면 처리 없음 | 녹음 동의를 내리면 인터뷰 화면의 마이크가 실제로 비활성화됨 |
| 비의료적 활동 (원칙 7) | 관찰 반응은 **눈으로 본 행동**만. 기분·인지·진단 항목이 존재하지 않음 |
| 권리 보호 (원칙 14) | 음악 스타일 목록에 실존 가수·곡 모사 항목이 없음 |
| 유아화 금지 (원칙 15) | 레벨·퀘스트·캐릭터 없음. 성취는 앨범과 기록으로 표현 |

## 접근성

WCAG 2.2 AA를 목표로 하고, 자동 검사로 회귀를 막습니다.

- 본문 대비 4.5:1, 큰 글씨 3:1 이상 — 전 화면 통과
- 모든 조작 대상 24×24px 이상, 핵심 CTA는 60px 이상
- **글자 크기** 조절(보통/크게/아주 크게)이 앱 전체 타이포를 실제로 확대
  (모든 글자 크기가 `rem`, 루트 폰트 크기가 `--text-scale`을 따름)
- 200% 확대에서 가로 스크롤·내용 손실 없음
- 키보드 이동 가능, 포커스 링 3px 상시 표시
- 핀치 줌 비활성화하지 않음

> 디자인의 선명한 주황은 그대로 두되, **18.66px 미만 글자를 얹는 주황 면**은
> 대비를 위해 어두운 톤(`brand-700`)을 씁니다. 원본 색을 최대한 유지하면서
> AA를 만족시키기 위한 규칙입니다.

## 데이터

이 빌드는 **모든 기록을 기기에만** 저장합니다(`localStorage`). 어르신의 음성·
이야기·가사는 서비스 밖으로 자동 전송되지 않습니다. STT·LLM·음악 생성 벤더를
붙일 자리는 `lib/services.ts`에 인터페이스로 열어 두었고, 멱등키·벤더 지역
고지·모델 버전 기록 같은 명세서 의무가 타입에 들어 있습니다.

## 자산

일러스트 76종은 `누끼.zip`에서, 로고는 디자인 PDF 1페이지에서 추출했습니다.
`scripts/prepare-assets.py`가 잘라내기·리사이즈·WebP 변환·매니페스트 생성을
한 번에 처리하며, 원본 92.4MB를 1.7MB로 줄입니다.

```bash
python scripts/prepare-assets.py
```

## 범위 밖

기능명세서가 명시한 제품 경계를 그대로 따릅니다: 의료 진단·치료, 장기요양 ERP,
공개형 커뮤니티, 보이스클론, 특정 가수·곡 모사, 평가점수 자동 보장, 기성곡
재생, 어르신 얼굴의 AI 변형, 게임화 세계관은 만들지 않습니다.

또한 이 저장소는 **복지사(사회복지사) 앱**입니다. 기능명세서의 센터장 콘솔,
가족 전용 화면, 시스템관리 콘솔은 아직 구현하지 않았습니다.
